أولاً: ما تم بناؤه وجاهز برمجياً







نواة المساعد التفاعلي المجاني (Free Guided Assistant):





src/lib/prompt/templates.ts: تم إنشاء 10 قوالب احترافية ثنائية اللغة (برمجة، VBA/Excel، استراتيجيات، تحليل بيانات، تدقيق أمني...) مع دالة الفرز والمطابقة التلقائية matchTemplates().


src/lib/prompt/assistantFiles.ts: تم بناء قارئ ملفات محلي 100% يعمل داخل المتصفح (Client-side) يدعم قراءة ملفات النصوص والـ CSV، ومصنفات الإكسيل (.xlsx, .xlsm) واستخراج أوراق العمل والخلايا دون إرسالها لأي خادم ودون استهلاك أي كريدت.


src/lib/prompt/requestAssistant.ts: دالة synthesizeRequest() تجمع إجابات المستخدم، والملفات، وتنشئ كائن Specification وAdvancedControls مع تفعيل تلقائي لقيود منع الهلوسة وعقد المخرجات وعزل المتغيرات {{input}}.


src/components/RequestAssistant.tsx: واجهة المساعد التفاعلية (5 مراحل: اقتراح القوالب المناسبة، حوار خطوة بخطوة عبر 3 أسئلة، استعراض المواصفات، والاعتماد).









محركات الفحص والحوكمة والتخزين:





تم دمج محرك القرارات (decisionEngine.ts) ومحرك فحص القواعد (linter.ts) وبوابة الجاهزية (readiness.ts).


تم إعداد قاعدة بيانات Lovable Cloud وجدول prompt_registries بنظام صلاحيات RLS لحفظ السجل والمكتبة.


فحص الأخطاء البرمجية للمشروع بالكامل نظيف تماماً (tsgo Exit Code: 0).










ثانياً: ما المتبقي برمجياً بالتفصيل (Pending Tasks)


1. ربط المساعد التفاعلي بواجهة التطبيق (Workbench.tsx) — (الأولوية العاجلة)




الوضع الحالي: كود المساعد RequestAssistant.tsx مبني كملف مستقل، لكنه غير مستورد (Not imported) في Workbench.tsx.


المطلوب برمجياً:



استيراد المكوّن في Workbench.tsx:

import { RequestAssistant } from "@/components/RequestAssistant";





تثبيته في الواجهة مباشرة أعلى خانة إدخال المهمة (section.workbench-request).


ربط دالة الاعتماد onAdopt:

onAdopt={(draft) => {
  setInput(draft.source);
  setSpec(draft.specification);
  if (draft.specification.advanced) setAdv(draft.specification.advanced);
  setPlaygroundInputs(draft.inputValues);
  run(); // تشغيل فوري لتوليد البرومبت وإظهار النتائج
}}


بذلك، بمجرد أن ينهي المستخدم الحوار مع المساعد، تُملأ كل حقول التطبيق المعقدة تلقائياً ويُولد البرومبت وتظهر شاشات الفحص مباشرة.










2. استكمال تعريب نتائج محركات الفحص وشاشة النماذج




الوضع الحالي: واجهة التطبيق معربة بنسبة 95%، لكن النتائج التي تصدرها المحركات نفسها (رسائل الـ Linter وأسباب منع الجاهزية) تصدر بنصوص إنجليزية ثابتة، وشاشة النماذج ModelSettings.tsx تحتاج بطاقات وشروحاً عربية.


المطلوب برمجياً:



إنشاء دالة ترجمة تشخيصية DIAGNOSTIC_TRANSLATIONS_AR داخل src/lib/i18n.ts لتحويل أسباب الملاحظات (مثل Language Mismatch، Missing Constraints) إلى العربية عند اختيار واجهة اللغة العربية.


تحديث ModelSettings.tsx بإضافة بطاقات تعريفية لكل نموذج باللغة العربية (مثل: OpenAI o1/o3 للمنطق العميق، Claude 3.5 للأكواد، Gemini 2.0 للسياق الضخم، DeepSeek R1 للتفكير منخفض التكلفة).










3. تصحيح ملف اختبار محركات الفحص (tests/prompt-engines.test.mjs)




الوضع الحالي: جميع الاختبارات الأخرى تجتاز بنجاح (المطابقة، المقارنة، النماذج، الحواجز الأمنية)، ولكن prompt-engines.test.mjs يعطي خطأ NameTooLong بسبب استخدام كود مشفر بـ base64 داخل مسار الاستيراد.


المطلوب برمجياً: تعديل ملف الاختبار ليستورد الدوال مباشرة من مسار المشروع src/lib/prompt/ ليعود شريط الاختبارات بالكامل أخضر.






4. البنية التحتية للتحويل إلى SaaS مدفوع وتطبيق أندرويد (المرحلة القادمة)




بوابة الدفع والاشتراكات:



إنشاء جدول user_subscriptions في قاعدة بيانات المشروع لتسجيل نوع الباقة (Free / Pro / Enterprise) وتاريخ التجديد.


إضافة مسار خادم src/routes/api/public/stripe-webhook.ts لمعالجة عمليات الدفع عبر Stripe أو Paddle.






تطبيق Android (Google Play):



تثبيت CapacitorJS (@capacitor/core و @capacitor/android) لتغليف تطبيق الويب كحزمة Android أصلية دون إعادة برمجة الكود.


توليد مفتاح التوقيع الرقمي وحزمة .aab وربط نظام الدفع الداخلي لـ Google Play.










الخطوة التالية المقترحة



نبدأ الآن بربط المساعد التفاعلي المجاني (RequestAssistant) داخل Workbench.tsx واختباره عملياً في المعاينة لتتمكن من تجربة الحوار وتعبئة الحقول آلياً؛ هل ترغب بالانتقال لوضع البناء لتنفيذ هذا الربط فوراً؟
